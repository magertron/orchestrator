Solutions · Network operations

Self-Healing Networks

With an operator on every change

Network teams are wiring agents to alarms so faults are fixed in minutes. Magertron™ governs those agents on the message bus itself, so the agent that diagnoses a fault cannot also push the fix.

The risk

An agent that can reroute traffic can take a network down.

Agents read alarms from Kafka or ZeroMQ, check the network and publish commands. If any agent can publish anything, one bad diagnosis or one injected message becomes a change in production.

Magertron checks every publish, subscribe and tool call against roles and policy, and carries one trace from the alarm to the fix.

How it plays out

One fibre cut, step by step

  1. A fibre is cut. The network raises an alarm on the bus.
  2. AllowedThe diagnosis agent reads the alarm and checks the network, read-only.
  3. RefusedIt tries to fix the fault itself. Diagnosis agents can't change the network.
  4. AllowedIt publishes its diagnosis.
  5. AllowedThe operator agent, acting for the on-call engineer, publishes the fix to the commands topic. Only operators may.
  6. The executor, on another host, reroutes traffic. The network is back.
  7. RefusedRemove the engineer's operator role and cut the fibre again. The operator's fix is refused, naming the engineer, and the network waits for a person.
What does the work

The controls

  • Topic permissions. Who may publish and subscribe, per topic: diagnosis agents publish findings, only operators publish commands.
  • Acting for a person. The operator agent acts for a named engineer. Take away the engineer's role, and the agent loses it too.
  • Same rules on either bus. The same agents and the same policy on Kafka or ZeroMQ.
  • One trace, alarm to fix. The trace travels inside each message, so every agent's step lands in one OpenTelemetry trace.
  • Deterministic or LLM-driven. Magertron governs the calls either way.

Questions

Frequently asked

▸Which message buses does Magertron govern?

Kafka and ZeroMQ, with the same agents and the same policy on either.

▸Does it need an LLM in the loop?

No. The agents can be deterministic scripts or LLM-driven. Magertron governs their calls either way.

▸How quickly does a removed role take effect?

On the agent's next call once the change has propagated, about 30 seconds in our lab.
