01

Get a credential

Trade your agent's token for a five-minute Magertron™ token. Cache it; refresh before it expires.

02

Read the catalogue

Ask what may be called. Each tool comes with the platform's verdict for the principal asking.

03

Call the tool

JSON-RPC over HTTP, with an idempotency key so a retry is never billed twice.

mc, _ := magertron.New(magertron.Options{GatewayURL: "https://mcp.acme.com"})

// 1 · a credential: your agent's token, exchanged for five-minute ones
agent := &magertron.Exchange{Client: mc, Subject: magertron.StaticToken(saToken)}

// 2 · what may you call?
tools, err := mc.Catalog(ctx, agent)

// 3 · call it — authorized, metered, audited, and retried safely
out, err := mc.CallTool(ctx, agent, tools[0], json.RawMessage(`{"timezone":"UTC"}`))

var r *magertron.Refusal
if errors.As(err, &r) && r.Kind == magertron.KindSpendLimit {
    // a human must lift the limit — tell someone, do not retry
}

Two identities, one call
The agent acts.
The person is accountable.
Every delegated call carries both identities, signed together by the platform. It can never reach further than the agent could alone — and the bill goes to the person who asked.

The person's token says who it is for; the agent's says who is acting. The exchange signs them into one five-minute token, so an agent cannot quietly drop the person — or add one.

Magertron™ is not another agent framework. It sits underneath the one you already use — anything that can make an HTTPS call.

PATH A

Magertron™ issues the tokens

No identity provider needed. An administrator creates the service account — in the console, through SCIM or with Terraform — and Magertron™ signs its token.

  • One service-account token, held in your secrets manager
  • Exchanged for five-minute tokens on every call
  • Acting for a person: an admin issues the person's token, and the same exchange binds the two
PATH B

Your directory issues them

Already on Auth0, Entra ID or another OIDC directory? Your agent gets a token from it with client credentials, and Magertron™ exchanges it.

  • Long-lived secrets stay in your directory
  • Magertron™ tokens never outlive five minutes
  • Acting for a person: their directory token is the subject, yours the actor
When it says no
Know which refusals
to retry.
Most refusals are decisions; retrying one only adds load and noise. The client applies these rules for you.
RefusalRetry?Why
403 No permission for …Once, after re-exchangingA token carries the roles held when it was minted. A newly granted role arrives with a fresh token.
429 PDP at capacity …Yes, with backoffLoad shedding — no decision was made, and nothing was billed.
429 Spend limit reached …NoThe budget stopped the call before it was billed. A person must lift the limit.
403 tool-approval: …NoThe vendor changed the tool. Calls resume once a human approves the change.
403 … non-delegable role …NoAn agent may never act for an administrator. By design.
Network error on tools/callYes, same keyThe same Idempotency-Key means the call is metered once, however many times it arrives.

⚿

Credential injection

Your agent never sees a vendor API key. It presents its own identity; the gateway attaches the credential upstream.

◈

Tool approval

If a vendor changes a tool's schema, calls stop until a human reviews the difference — regardless of your permissions.

▦

Metering by person

Every call is attributed to the identities on it. Delegated calls bill the person, with your agent shown alongside.

⛊

Budgets that hold

A call that would exceed the contract's ceiling is refused with a 429 — not billed and apologised for later.
